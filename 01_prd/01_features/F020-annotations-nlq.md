# F020 — In-App Annotations & Natural Language Query

**Area:** React Application  
**Priority:** Should / Could  
**PRD References:** FR-APP-11, FR-APP-12

---

## Situation

Financial dashboards generate questions and discussions — a controller sees an unexpected variance and needs to document the explanation; an executive wants to flag a data point for follow-up. Separately, not all users are comfortable with the pivot-style Explorer (F018) and would benefit from the ability to ask analytical questions in plain English. Both features enhance the platform's utility beyond static data display.

---

## Problem

**Annotations:** Without in-app commentary, discussions about specific data points happen in email, Teams, or verbal conversations — disconnected from the data. There is no audit trail linking a management comment to the specific data point it explains. Month-end commentary (required by most management reporting frameworks) is produced separately and cannot be associated with the underlying number at the source.

**NLQ:** Without a natural language interface, FP&A and executives without SQL knowledge cannot self-serve complex analytical questions. They must request queries from data engineering — a bottleneck. However, NLQ over regulated financial data carries a compliance risk if the underlying SQL is opaque: users must be able to see and validate the query that produced the answer.

---

## Action

### User Stories (Annotations)

- As a Group Controller, I can add a comment on any P&L line item in the dashboard explaining a variance, and that comment is visible to any authorised user viewing the same data point.
- As an executive, I can @mention the Group Controller on a flagged data point and they receive a notification via email or Teams.
- As a compliance reviewer, I can export all annotations for a given period as an audit trail.

### User Stories (NLQ)

- As the CFO, I can type "What is our EBITDA margin for Q2 vs Q1 by service line?" and receive an answer with the underlying SQL shown alongside it.
- As a compliance officer, I can see the exact SQL query used to produce any NLQ answer, so I can validate the methodology.

### Acceptance Criteria

**In-App Annotations (Should)**

1. Any tile, table row, or chart data point in F015, F016, F017, and F018 displays a comment icon on hover.
2. Clicking the icon opens a slide-out annotation panel for that data point context (identified by: view_id, entity, account, period, measure).
3. Users can create a new annotation: free-text up to 2,000 characters; supports markdown; can @mention any platform user by name (autocomplete from Entra ID directory).
4. @mention notifications sent via email (always) and Teams webhook (if configured); notification includes a deep link back to the annotated data point.
5. Annotations support threaded replies.
6. Annotations are visible to all users with access to the annotated data point's scope (entity-scoped for subsidiary controllers).
7. Annotation audit log: `(annotation_id, view_id, entity, account, period, author, created_at, content, edited_at)` — retained 7 years; exportable per period.
8. Annotations do not modify underlying data — they are metadata associated with a data point reference.

**Natural Language Query — NLQ (Could)**

9. NLQ pane accessible from a persistent icon in the application navigation bar.
10. NLQ pane accepts free-text questions scoped to the authenticated user's data access (entity scope from Entra group).
11. LLM generates a SQL query against the Gold schema and executes it via the F019 API layer — no direct lake access.
12. Response includes: (a) natural language answer, (b) the exact SQL query used, (c) a data table of the result, (d) a caveat if result confidence is low.
13. User can copy the SQL to use in Explorer (F018) or external tools.
14. Every NLQ session logged: `(session_id, user, question, generated_sql, execution_time_ms, row_count, timestamp)` — retained 7 years.
15. NLQ is scoped to Gold layer only; the prompt instructs the LLM not to access Bronze/Silver or any non-financial data.
16. LLM provider configured via Azure OpenAI (within the Azure tenant) — no data sent to third-party endpoints outside the tenant.
17. NLQ result includes a disclaimer: "This answer is generated by AI. Please verify the SQL and consult the data team for material financial decisions."

---

## Result

- Management commentary is captured at the source of the data — no separate commentary documents.
- Audit trail of all period-specific annotations available for external audit and regulatory review.
- Non-technical users can explore data in natural language without blocking engineering.
- NLQ transparency (SQL shown alongside answer) maintains auditability — no black-box answers on regulated financial data.

---

## Constraints

- **Priority:** Annotations are "Should" (Phase 1 if capacity allows); NLQ is "Could" (Phase 2 candidate).
- **Dependency:** F014 (React foundation), F019 (API layer) for both features.
- **Dependency:** F015–F018 (all views) — annotations hook into the UI interaction pattern of each view.
- **NLQ Dependency:** Azure OpenAI resource provisioned within the Azure tenant; LLM must have access to the Gold schema metadata (via Unity Catalog catalog description).
- **NLQ Dependency:** Prompt engineering and schema documentation quality directly determine NLQ accuracy — requires investment in Gold table and column descriptions.
- **Constraint (NLQ):** LLM-generated SQL must be read-only (SELECT only); API layer rejects any non-SELECT SQL from the NLQ endpoint.
- **Constraint (NLQ):** NLQ accuracy on complex multi-entity, multi-period queries is not guaranteed; the feature is an aid, not an authoritative source. The SQL transparency requirement is non-negotiable for compliance.
- **Constraint (Annotations):** @mention notifications require a Teams webhook or email integration to be configured; this is an infrastructure dependency separate from the annotation feature itself.
